## 2023-10-27 - Cache Key Generation Overhead
**Learning:** In Go, using `fmt.Sprintf` for constructing strings in highly-frequent hot paths (like cache lookups per embedding input) causes measurable overhead due to reflection and interface boxing, adding unnecessary allocations compared to standard string concatenation.
**Action:** Replace `fmt.Sprintf` with `strconv.Itoa` and simple string concatenation `+` in hot paths, and consider adding fast-path hardcoded values for frequently used parameters (e.g. dimensions 512, 1024) to avoid string conversion entirely.
## 2023-10-27 - RedisCache Key Generation Allocation Bottleneck
**Learning:** In hot-paths like cache lookups per request, dynamic string concatenations (`prefix + namespace + ":"`) and allocations from `hex.EncodeToString` create unnecessary GC pressure. `hex.EncodeToString` dynamically allocates a byte slice on the heap.
**Action:** Pre-compute static key prefixes in struct fields. Use stack-allocated byte arrays (`var dst [64]byte`) combined with `hex.Encode` for hex string generation to eliminate heap allocations. Hardcode fast-paths for highly common parameters (like standard dimensions `1024`, `512`) to avoid `strconv.Itoa`.
