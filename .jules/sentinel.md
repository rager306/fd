## 2024-05-24 - Unauthenticated System Endpoints
**Vulnerability:** Critical readiness and health endpoints (`/health`, `/ready`, `/v1/healthcheck`) were blocked by authentication requirements when `FD_API_KEY` was set.
**Learning:** Load balancers and orchestration systems (like Kubernetes) often probe health check endpoints without authentication. If they are blocked by a global API key requirement, the service might be incorrectly marked as unhealthy and terminated.
**Prevention:** Ensure all liveness, readiness, and health-check endpoints are explicitly excluded from global authentication middleware.
## 2025-02-15 - Timing Attack via Length Short-Circuiting in Go
**Vulnerability:** Length-based timing oracle in authentication middleware caused by `subtle.ConstantTimeCompare` returning immediately on length mismatch.
**Learning:** `subtle.ConstantTimeCompare` is strictly constant-time *only* for slices of equal length. Passing tokens of arbitrary length directly allows attackers to measure validation time to guess valid token lengths.
**Prevention:** Always verify lengths match before invoking `subtle.ConstantTimeCompare`. To avoid leaking information via a conditional short-circuit branch, perform a dummy comparison (e.g., `subtle.ConstantTimeCompare(secret, secret)`) when lengths mismatch to strictly balance execution time.
## 2025-02-15 - Fixing CI Lint Failure caused by Glob Patterns in regex exclusions
**Vulnerability:** Not a direct security vulnerability, but a CI configuration failure affecting repository pipeline integrity. The CI pipeline reported multiple pre-existing linting failures globally (e.g., `errcheck`, `goconst`, `gocritic`), despite the user requesting we not bloat PRs with unrelated global fixes. The root cause was discovered in `.golangci.yml`: an invalid path pattern (`"**/*_test\\.go"`) was being evaluated using Go's regex engine instead of a glob engine, triggering a parsing failure that effectively disabled the configured exclusions.
**Learning:** In `.golangci.yml`, the `path` key under `exclude-rules` expects Go regular expressions (RE2 syntax), not doublestar/glob syntax. Passing glob syntax like `**/*_test\\.go` results in an invalid regex and causes the exclusion logic to silently fail or parse incorrectly.
**Prevention:** Always ensure `path` fields in `exclude-rules` use valid RE2 regex (e.g., `.*_test\.go`) and test `golangci-lint run ./...` locally.
